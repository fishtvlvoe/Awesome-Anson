# 2026-09-01 市場運營／企業 AI 導入（會後規格）

會議日期：2026-09-01。逐字稿中段有斷訊，主體以現場確認＋Fish 補的會議紀要為準。客戶公司名未入檔。這份是部門分類與架構 SSOT，給另一台電腦接續。不報價、不寫碼。

## 客戶目標

各部門核對、重複作業請不到人；工作本質不難，但學很久又無聊，教育手冊落後。人一走就交接斷。主管希望問得到會議與制度，不用一個一個問人。最後要資料自己進來、自己核對，下面夥伴能力門檻變低。

不做：一次上所有部門 Agent；不上完整機器人就對外出；這輪不報價；不把客服、行銷生圖、營運分析混成一案開工。

## 總架構（四層，由下而上）

1. 資料源：Google Drive、Workspace 信箱（轉換中，仍有人用個人 Gmail）、Meet、Calendar、LINE、LINE WORKS。
2. 資料底：取得、結構化、治理、權限、品質（垃圾資料要能攔）。有 API 就自動每天拿，少轉 Excel。
3. 公司腦：會議助理／公司 HI。問得出「上週四下午會議講什麼」。會議開頭養成講部門、目的。
4. 崗位 Agent：資料底打好後，一個部門一個部門上。人過目再送，不是機器人直回客人。

LINE WORKS 有官方 API（Bot、訊息、檔案、團隊）。正式 Meet 可開錄音讓 AI 吃；臨時會可能沒錄，可用 LINE 丟音或手機錄音上雲。

## 部門分類

跨部門現況：商品市場運營 ↔ 商品採購；市場運營 ↔ 行銷；商品採購 ↔ 管理；市場運營 ↔ 管理。每個部門都說核對型工作找不到人。第一個訪談部門未定。

### A. 市場運營（第一優先候選）

內容：通路資料、訂單／入駐、Google 評價、LINE 大量回報、營運預覽。
痛點：核對、重複作業、缺人。
架構：吃通路 API＋內部知識庫 → 營運分析 Agent；客服類回報走 LINE，人過目。
先做：盤點每天最花時間的核對項；標出有 API 的通路。
後做：營運 AI 管理、自動報表。
適合的人：蓋神（串接／崗位 Agent）、庫神（知識庫歸位）。

### B. 客服／營運部助理

內容：訂單、入駐狀況、評價、LINE 來回。
痛點：重複問答、核對、手冊落後。
架構：知識庫表（問句／情境／分類／怎麼回）＋當下草稿輔助。人最後看過再送。
先做：現有 Excel／對話紀錄能不能當第一批知識。
後做：直回客人的機器人。
適合的人：蓋神、庫神。

### C. 商品採購

內容：與市場運營、管理交接的採購流程、對帳、進貨核對。
痛點：同類核對、學很久、請不到人。
架構：流程寫進知識庫；對帳／核對類 Agent（類比：金流對帳自動進表，人只管例外）。
先做：訪談「每天核對什麼、手冊哪裡過時」。
後做：全自動對帳。
適合的人：蓋神。

### D. 行銷／社群小編

內容：大量發文、內容、可選影像生成。
痛點：產出量大。
架構：知識庫提供產品／制度脈絡後，才上行銷 Agent。
先做：不要當第一波。
後做：發文 Agent、影像生成串接。
適合的人：之後才叫導演／文案師；這輪不派。

### E. 管理／主管

內容：各部門開會有沒有開、交件有沒有交；想直接問 AI 代替問人。
痛點：每天擔保不同、跨部門問不完。
架構：公司 HI＋會議助理；提醒開會、整理決策；只答會議裡發生過的。
先做：Meet 錄音權限、會議開頭習慣。
後做：固定排程提醒與週報。
適合的人：蓋神、小歐（盯會後行動）。

### F. 知識庫管理員（跨部門崗位，不是一個現有科室）

內容：制度、脈絡、會議、手冊入庫；離職交接「不知道怎麼做、做了什麼」。
痛點：資料斷層、找資料慢、品質不齊。
架構：圖書館管理員比喻——會認真整理你餵的所有東西，所以要能辨識垃圾資料、呈請人批準或丟掉。
先做：第一波資料源清單＋權限＋品質規則。
後做：自動分類、少人工標籤。
適合的人：庫神（歸位）、蓋神（pipeline）。
