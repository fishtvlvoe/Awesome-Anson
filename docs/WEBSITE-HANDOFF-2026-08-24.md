# 案神使用說明網站｜交接文件

> 交給接手網站的代理。這份文件只處理 `anson-manual.pages.dev` 說明書網站，不處理剪神影片生成。

## 1. 目標

把案神做成「不懂工程的人看了就知道在做什麼」的個人說明書網站。它是文件／操作說明介面，不是 SaaS 後台，也不是 Cloudflare 上的產品系統。

公開入口：`https://anson-manual.pages.dev/`

原始參考：使用者提供的案神視覺稿，以及課神既有的 UI／UX 風格。品牌風格統一讀工作區根目錄 [`DESIGN.md`](../../DESIGN.md)，不可在本專案另造色票、字體或元件規則。

## 2. 目前可重用的程式

- 主頁：`dashboard/index.html`
- 版本資料：`dashboard/entries/manifest.json`、`dashboard/entries/v1.json`、`v2.json`、`v3.json`
- 狀態：`dashboard/state.json`
- 現有案例互動：`dashboard/index.html` 內的 `[data-case-demo]` 與 `initCaseDemo()`
- 現有契約：`contracts/`、`openspec/specs/case-page/spec.md`
- 現有公開部署背景與邊界：`README.md`

先讀現有程式與 `git status`，不要重寫一個平行網站。

## 3. 使用者要看到的主敘事

首頁第一屏先講結果，不先講 Agent 名稱或技術：

> 客戶把需求、錄音、聊天紀錄、Word／Excel／PDF、手寫筆記交給你；案神幫你整理成可以確認、可以報價、可以提案的成果。

最後交付物要直接看得到：

1. 簡報檔
2. 網站／Demo
3. 程式代碼
4. 服務報價說明書

每個交付物都要補一句白話用途：它解決客戶哪個問題、客戶拿到後下一步能做什麼。

## 4. 必須新增／修正的內容

### A. 真實案例，不是只有流程圖

「先看案例」必須開啟兩個匿名化的真實接案案例。每個案例要有：

- 客戶原本怎麼說（保留模糊、零碎的真人語氣）
- 案神怎麼追問與整理
- 真正的問題是什麼
- 提供了哪些方案
- 客戶最後拿到哪些成果
- 這個成果替客戶省掉什麼麻煩

案例圖片要與敘事一起出現；不可只放一張抽象流程圖，也不可只放英文技術名詞。

### B. 無限畫布概念的視覺示意

做一張「看起來像無限畫布、但不需要真的拖拉」的示意圖，旁邊一定要有標題和白話流程：

```text
1. 收集原始資訊：錄音、確認需求、文字聊天、Word、Excel、PDF、手寫筆記
2. 進入案神：統一彙整、找出真正問題、標記已確認／待確認／只是猜測
3. 產出成果：簡報、網站／Demo、程式代碼、報價說明書
4. 人工確認後成交或進入蓋神開發
```

圖只是說明用，不做拖拉畫布功能。每個節點要有示意圖片或小圖卡，讓小白能想像「畫面會長什麼樣子」。

### C. 客戶 → 案神 → 人工確認 → 交付 → 成交

要明確畫出五個節點，並說清楚責任邊界：

- 客戶：提供需求與資料，不需要懂工程。
- 案神：整理對話、找出真正問題、提出方案候選、產出 Demo／文件草稿。
- 人工確認：PM／業務確認內容和範圍，AI 不可替人答應價格。
- 交付：簡報、網站、程式碼、報價說明書。
- 成交：CTA 是「與我們聯繫」，再導向 GitHub；未來可接付費 SaaS。

### D. 技術名稱放下方查對

畫面主標使用白話用途，例如「把客戶的話整理成可以報價的需求」。技術名稱只放在卡片下方的小字，例如 `project-manager`、`case-page`、`engagement-quote`，不可讓技術名詞搶走主敘事。

### E. CTA

頁面最後要有一個清楚的「與我們聯繫」按鈕，至少包含：

- GitHub 倉庫連結：`https://github.com/fishtvlvoe/Awesome-Anson`
- 未來付費版的預留說明，但不能假裝目前已經有 SaaS 入口。

## 5. UI／UX 固定規則

- 以課神既有的低 AI 感、文件型、清楚分層視覺為基準；不要改成霓虹、玻璃擬態、漂浮全息卡片或過度動畫。
- 讀取根目錄 `DESIGN.md`：色票、字型、間距、圓角、陰影、動畫全從那裡來。
- H1 只留一個；區塊用 H2；卡片標題用 H3。不要把整段說明做成超大標題。
- 圖片不是裝飾：每張圖片旁邊要有「這張圖在說什麼」的一句白話。
- 動畫只用來表示流程順序或案例切換，不能讓使用者等動畫才看得到內容。
- 手機版要能讀完流程；四步案例不可因響應式而變成看不懂的橫向溢出。

## 6. 不要做的事

- 不把 Cloudflare Pages 文件站改成 SaaS 操作後台。
- 不把「案例」做成只有四步流程圖。
- 不把客戶名字、真實個資或未授權圖片放上去。
- 不把未完成的即時語音、公開 HTTPS 收音、付費 SaaS 說成已經完成。
- 不再為說明圖輸出 SVG；網站用正常的 PNG／JPG／HTML 圖卡即可。
- 不碰剪神影片生成、Flow、Seedance 或 fal.ai 工作。

## 7. 驗收條件

接手代理完成後，必須實跑並回報：

1. `dashboard/index.html` 可離線直接開啟，案例按鈕可切換兩個案例。
2. 首頁第一屏能在 10 秒內看懂「案神整理什麼、最後拿到什麼」。
3. 無限畫布示意圖旁有完整四步白話說明，且五個串接節點可辨認。
4. 每個主要節點至少有一張能對應內容的示意圖／圖卡。
5. CTA 的 GitHub 連結可點擊；整頁沒有未定義的連結、圖片 404 或水平滾動。
6. 以瀏覽器截圖驗證桌面與手機寬度；測試輸出要附檔案路徑，不可只說 build 通過。

## 8. 接手順序

1. 先讀 `dashboard/index.html`、`dashboard/entries/v3.json`、`README.md` 與根目錄 `DESIGN.md`。
2. 先做本地 HTML 預覽，不發布正式網址。
3. 讓 Fish 看本地畫面確認後，再依部署規則處理 `anson-manual.pages.dev`。
4. 完成後建立獨立 SR／PR，避免把影片或其他神系列的變更混進來。
