# 覆盤

呼叫名稱：`/覆盤`
使用 `$` 格式的 Agent 介面時，也可輸入 `$覆盤`。

把已發生的合作整理成可查證、可交接、可複製的工作方法。適用於案件結束、合作卡住或需要把經驗交給業務時；不負責報價、客戶人格判斷或部署。

## GATE：先分開這一輪要做什麼

先宣告本輪是：

- **覆盤清點**：還原已發生的事、證據、責任、瓶頸與可複製規則。
- **後續計畫執行**：針對已確認的 Action 排程、實作或追蹤。

兩者不可混做。若同時出現，先完成覆盤清點，再另開後續計畫；宣告後只問一題，等 Fish 確認。事實可由 Agent 查檔案、逐字稿與交付物，不問使用者已能查到的內容。

## 工作流程

1. 建立覆盤台帳，盤點人、事、時、地、物與交付物；每筆資料附來源與狀態：`confirmed`、`recalled`、`inferred`、`pending`、`action`。
2. 一題一題補齊最關鍵的未知決策；查不到的事實保留 `pending`，推論不得升格成結論。
3. 用 `F/N/G/A` 整理：Future（下一案可複製規則）、Now（目前看到的狀況）、Gap（差距或未知）、Action（有 owner 與期限的動作）。
4. 檢查合作節奏：決策者、執行窗口、回覆時間、決策期限、認知分歧的裁決者；標明這是覆盤檢查點，不改寫成客戶當時已同意。
5. 先交付文字覆盤與交接內容，等資料確認後才一次性產出單頁 HTML；過程中不逐輪改 HTML。
6. 交給「網頁設計師」時，先傳完整事實、狀態、結構與驗收清單；設計不能取代事實判斷。

## 強制停止點

- 模式判斷未經 Fish 確認，不進入覆盤提問或後續執行。
- 文字覆盤仍有關鍵 `pending`，不產出定稿 HTML，也不把它寫成客戶承諾。
- HTML 內容與結構未經確認，不交給設計或發布。

## 品質檢查

- [ ] 人／事／時／地／物／交付物都有來源與五種狀態之一。
- [ ] 每輪只有一題；可查事實已由 Agent 查檔案，猜測仍標示。
- [ ] F/N/G/A 分開現在狀況與下一案規則。
- [ ] 文字中立，未替客戶下人格判斷，未把 PM 問題擴成客戶內部管理責任。
- [ ] 交接包含始末、關鍵證據、決策瓶頸、角色責任、決策期限與未確認事項。
- [ ] HTML 有流程圖、角色責任、F/N/G/A、下一步，且通過完整性與手機可讀性檢查。

## 完成條件

- [ ] 覆盤／執行模式已分開，且 GATE 已通過。
- [ ] 文字覆盤、業務交接與所有 `pending` 已留存；`action` 有 owner／期限。
- [ ] 單頁 HTML 只在最後一次產出，使用相對連結，未把未確認內容偽裝成結論。
- [ ] 未自動部署；發布需等使用者另行指定。

詳細欄位、問法、交接與 HTML 契約見 [knowledge/retrospective-framework.md](knowledge/retrospective-framework.md)；可直接複製的格式見 [TEMPLATES.md](TEMPLATES.md)。
