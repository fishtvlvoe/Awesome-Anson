# 專案掌控與提案會議原則

Fish 自己的接案方法論，供 `pm-discovery-upgrade` 訪談與 `project-manager` Agent 判斷案件複雜度、設計檢查點時參考。

## 專案分配前：風險評估與工作分配會議

1. 該專案的市場機會是什麼
2. 專案的商業模式與完成目標是什麼
3. 會對專案造成阻礙的可能性有哪些
4. 專案由什麼樣類型的團隊執行最合適
5. 專案的總負責人是誰，工作分配目標是什麼

## 專案分配時：設定檢查點

依專案重要程度設定回報頻率：最大以週或日為單位，最小以小時為單位。

## 專案進行時：以終點為起點

確保專案準時交付，不應有閃失；風險評估與檢查點做得好，會高度提升效率。

## 提案會議：備、前、中、後、結 五階段

| 階段 | 重點 |
|---|---|
| 準備 | 無簡報：先確認會議時間；有簡報完整提案：先備妥完整簡報 |
| 會議前 | 會議時間、地點、與會人員、會議類型、議程、重點、目標、相關資料；若只需快速提案，備簡版簡報 |
| 會議中 | 識別真正決策者、記錄所有發問細節、觀察與會人員專注狀態、確認行動方案 |
| 會議後 | 確認問題與建議是什麼、確認行動計畫、確認目標是否達成 |
| 結案 | 撰寫結案報告、進行檢討會議、內外部公開分享 |

## 原則

被問到不懂的問題，就說不知道，不要唬爛。
