# Path 判斷依據與欄位收集細節

配合 `SKILL.md` 使用，這裡收錄 GATE 兩層判斷的完整依據，以及步驟 1 各路徑的欄位收集規則。

---

## 第一層：Path A / Path B 判斷依據

- 有清楚的逐頁/逐段結構 + 大量已成形文字 → Path A
- 只有標題、幾個關鍵字、口頭描述 → Path B
- 介於兩者之間、判斷不出來 → 傾向 Path B（缺欄位一題一題問補齊，比替使用者腦補內容安全）

---

## 第二層：是否疊加「逐頁詳細規格版」

不是第三條獨立路徑，是蓋在 Path A 或 Path B 之上的加強模式（比一般模板更嚴格：強制 hex 色碼、指定字體、強制逐頁展開規則）。

宣告句式擴充為：「判斷走 Path A / Path B（+ 詳細規格版），因為 ___」

**觸發條件（符合任一即疊加）：**
1. 使用者明確要求「這是要給外部/正式場合看的提案，需要精確的視覺控制」
2. 使用者提供的輸入內容本身已經包含逐頁的視覺規格（標題＋重點＋配圖建議＋色碼等）

**判斷依據：**
- 內部使用、簡單概要提詞、沒人要求精確視覺 → 不疊加，走一般 Path A/B 模板即可
- 對外正式場合（提案、合作邀約、客戶簡報）＋ 使用者明確要求精確視覺控制 → 疊加詳細規格版
- 輸入內容本身已經是逐頁規格文件（每頁都寫好標題/重點/配圖建議，甚至色碼）→ 疊加詳細規格版，不論底層走 Path A 或 Path B
- 不確定 → 傾向不疊加（一般模板已覆蓋官方 6 要素，沒被要求就加規格是替使用者做過多假設）

---

## 步驟 1：Path A — 直接萃取，不問常規 intake 問題

直接讀取提供內容，萃取以下欄位，不要另外問一輪標準問題：

- 主題（看標題、開場如何定義主題）
- 受眾（看文案稱呼的對象、用詞程度、舉例情境）
- 頁數（數清楚分頁數量，如「Slide 1」～「Slide N」或段落數）
- 語氣（看用詞是正式書面還是口語互動）
- 風格（看文案裡的視覺描述、配色、排版線索）
- 逐頁重點（每頁摘成一行）

若某個欄位在原文完全找不到線索（例如整篇看不出受眾是誰），才單獨追問那一項，不重複問已經能萃取到的欄位。

---

## 步驟 1：Path B — 一題一題問缺的欄位

依序問，**每次只問一題**，等使用者回答後才問下一題：

1. 主題是什麼？
2. 受眾是誰？（身份/程度）
3. 大概要幾頁，或預計講多久？（換算成頁數）
4. 語氣要怎麼定？（封閉式問題，依「跨代理選單原則」用編號清單問）
   ```
   1. 正式
   2. 口語化
   ```
5. 有哪些重點一定要強調？

問完全部題目才往下走，不可以自己腦補跳過任一題。

---

## 詳細規格版加問（GATE 判斷疊加時才需要，Path A / Path B 通用）

若 GATE 判斷疊加「詳細規格版」，在各自路徑之外，額外收集：

- 主色 hex 色碼（例：`#0b1020`）
- 強調色 hex 色碼（例：`#38bdf8`）
- 輔助色 hex 色碼（若有品牌色需對應才需要，非必要）
- 指定字體（中文字體＋英數字體，例：Noto Sans TC ＋ Inter）
- 逐頁配圖／Icon 建議（每頁至少一則）

**Path A**：若原文已經逐頁寫好這些欄位（像「頁 N｜標題」＋配圖建議＋色碼那樣的規格文件），直接萃取，不用另外問。
**Path B**：這些欄位原本不在標準 5 題裡，比照「一題一題問」規則追加問，問完才往下走。

使用者答不出精確 hex 色碼時，可以建議 2-3 組候選色碼供選，但選擇權必須交還使用者確認，不可以靜默帶入自己編的預設值。
