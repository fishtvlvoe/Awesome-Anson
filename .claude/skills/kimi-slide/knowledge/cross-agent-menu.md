# 跨代理選單原則（全程適用）

這個 skill 可能在 Claude Code、Codex CLI 或其他 agent 環境執行，不是所有環境都有結構化選單工具（例如 Claude Code 的 AskUserQuestion，Codex 沒有這個）。所以：

- **封閉式問題**（2-4 選一，例如語氣、是否疊加詳細規格版）：**預設一律用純文字編號清單**呈現選項，讓使用者回覆數字或文字即可，例如：
  ```
  語氣要怎麼定？
  1. 正式
  2. 口語化
  ```
  若執行環境是 Claude Code、且有 AskUserQuestion 工具可用，可以額外疊加使用該工具讓體驗更好，但純文字編號清單永遠是保底寫法，不可以只靠工具、假設工具一定存在。
- **開放式問題**（主題、受眾、重點這種答案不固定的）：維持直接純文字問，不用編號選單。

判斷結果請使用者確認時（GATE 兩層判斷完成後），依此原則用編號清單請使用者確認或覆寫判斷結果，不要直接默默往下走：

```
我判斷這次走：
1. 確認，照這個判斷繼續
2. 不對，應該走 Path A（完整逐字稿）
3. 不對，應該走 Path B（零散想法）
4. 不對，不用疊加詳細規格版 / 需要疊加詳細規格版
```

（實際呈現時把選項精簡成跟目前判斷相反的那 1-2 個即可，不用四個都列，例如已判斷 Path A 不疊加，就只需要「1. 確認」「2. 不對，應該是 Path B」「3. 不對，需要疊加詳細規格版」三選一。）
