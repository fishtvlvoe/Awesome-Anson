# Kimi Slide Prompt Generator

把「已有素材」或「零散想法」收斂成中繼 md，再轉成可直接貼給 Kimi PPT 用的生成提詞。

跨代理環境（Claude Code、Codex CLI 等）的選單呈現原則見 `knowledge/cross-agent-menu.md`，全程適用，尤其是封閉式問題（語氣、是否疊加詳細規格版）一律先用純文字編號清單保底。

## GATE：強制對焦（不可跳過）

收到任務後，第一步判斷輸入路徑並宣告「判斷走 Path A / Path B，因為 ___」：

- **Path A（完整逐字稿/文案）**：已有清楚分頁/分段結構、核心文字已成形
- **Path B（零散想法）**：只有主題、幾個重點、口語描述，沒有完整草稿
- 介於兩者之間、判斷不出來 → 傾向 Path B

再判斷要不要**疊加**「逐頁詳細規格版」（蓋在 Path A/B 之上的加強模式：強制 hex 色碼、指定字體、逐頁強制展開規則）。判斷依據與觸發條件見 `knowledge/path-judgment.md`。

兩層判斷完成、宣告理由後，依「跨代理選單原則」用編號清單請使用者確認或覆寫，例如：
```
我判斷這次走：
1. 確認，照這個判斷繼續
2. 不對，應該走 Path A / Path B
```

> **強制停止點：兩層判斷、宣告、且使用者確認完，才進入步驟 1。**

---

## 步驟 1：依路徑收集資訊

- **Path A**：直接萃取主題／受眾／頁數／語氣／風格／逐頁重點，只追問原文找不到線索的欄位
- **Path B**：一題一題問，每次只問一題：主題 → 受眾 → 頁數/時長 → 語氣（封閉式，依編號清單問）→ 要強調的重點
- **疊加詳細規格版時**：兩路徑通用，額外收集主色/強調色 hex、字體、逐頁配圖建議；答不出精確色碼時建議 2-3 組候選，選擇權交還使用者

完整欄位清單與追問規則見 `knowledge/path-judgment.md`。

> **強制停止點：Path B 問完所有題目／詳細規格版問完色碼字體，才進入步驟 2。**

---

## 步驟 2：收斂成中繼 md

依 `TEMPLATES.md` 的中繼 md 格式範本收斂（一般版或詳細規格版），產出後**停下來給使用者確認**。

> **強制停止點：使用者確認中繼 md 內容無誤，才進入步驟 3。**

---

## 步驟 3：必要欄位檢查

主題、受眾、頁數缺一不可產生提詞，不可用預設值靜默帶過。疊加詳細規格版時，主色／強調色 hex 也升級為必要欄位。缺的欄位回頭針對性追問。

> **強制停止點：必要欄位齊全且使用者已確認，才進入步驟 4。**

---

## 步驟 4：產出 Kimi 提詞

依路徑套用 `TEMPLATES.md` 對應模板（Path A／Path B／逐頁詳細規格版），需覆蓋 Kimi PPT 官方 6 要素（明確頁數、指定風格、受眾與目的、強調重點、語氣、可附完整來源文件；來源：https://www.kimi.com/zh-cn/help/ppt/ppt-overview）。若 {N} > 10，附續傳提示「繼續，從第 X 頁開始」。

已驗證過的三個實際案例（Path A/B/詳細規格版各一，含真實來源與 6 要素核對）見 `knowledge/worked-examples.md`；更多討論脈絡見 `knowledge/cases/`（只看格式與思路，不用照抄內容）。

---

## 品質檢查（必須執行，輸出驗證）

- [ ] 輸出格式符合對應路徑模板（Path A／Path B／詳細規格版三選一，不混用）
- [ ] Kimi PPT 官方 6 要素中至少覆蓋 5 項，逐項核對並列出核對結果
- [ ] 疊加詳細規格版時：逐頁展開規則已強制套用（不合併、不跳過、不摘要），無編造的色碼
- [ ] {N} > 10 時已附續傳提示

---

## 範圍界線（Scope boundary，強制聲明）

這個 skill **只產出提詞文字**。全程不呼叫任何 Kimi API、不自動送出、不自動貼上。最終貼到 Kimi 網頁版或 App，一律由使用者自己手動操作完成。

---

## 完成條件（全部達到才算完成）

- [ ] 主題／受眾／頁數（疊加時+主色/強調色）均齊全，無預設值靜默帶過
- [ ] 品質檢查已執行且通過
- [ ] 全文未包含任何自動呼叫 Kimi API / 自動送出 / 自動貼上的邏輯
