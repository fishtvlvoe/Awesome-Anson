# Demo Generation & Deploy（即時 Demo 生成部署）

一句話定位：把已確認的需求資料包，變成一個真的能上網、客戶當場能操作的 Demo。

## 調度原則：案神是統籌者，這裡不自主觸發

案神是整個接案流程唯一的大腦與調度者。`網頁設計師`、`案例設計師`、`簡報師`、`demo-generation-deploy`（本 skill）、`case-page` 平常各自能被單獨呼叫，但在一個進行中的案件裡，**沒有案神的判斷跟派工，這幾個都不自己動**——是案神看完當下狀況才決定要不要叫、叫誰、叫幾個，不是這個 skill 自己判斷「該我上場了」。

## 風格與內容前置階段（部署前必做，除非明確跳過）

**這個 skill 自己不產生視覺風格，也不寫敘事內容**——這是本次修正的核心：以前這裡會自己生成 Demo 的外觀，容易落入 AI 制式模板，也跟案神底下既有的風格專家重複造輪子。改成：

1. **委派 `網頁設計師`**（預設一定要）：讓它跑自己既有的 Phase 1（風格方向討論 → 參考 21st.dev/motionsites.ai/Pinterest，**加上 `案例設計師` 查 SaaSFrame 本地索引找真實案例**當額外參考來源 → `frontend-design` skill 把關避免制式模板 → 產出 HTML mockup → 使用者確認）。**只委派到 mockup 確認為止，不進 `網頁設計師` 自己的 Phase 2 部署流程**——它的 Codex sites-building/sites-hosting 部署路徑不處理 D1 登入後台，部署改由本 skill 自己接手
2. **視需要委派 `簡報師`**：需求資料包裡有敘事/簡報式頁面（例如產品故事、逐頁介紹）才委派，走它既有的逐頁結構確認流程，產出內容併入 `網頁設計師` 的 mockup；純功能性操作型 Demo（例如純後台系統示範）不需要委派
3. 兩者都確認後，本 skill 才拿確認過的 mockup + 內容進部署階段，**部署時不能自己再改風格**

**跳過委派 `網頁設計師` 只在一種情況允許**：Demo 完全沒有視覺呈現需求（例如純資料/純文字輸出，客戶用程式讀取不是用眼睛看）。跳過時，回報給使用者的內容裡**必須明講「這次跳過風格委派，因為 X」**，不能悄悄跳過不說明。

## 部署前置檢查：mockup 未確認不能部署

進入下方「本 skill 專責的部署行為」前，先確認風格前置階段（上一節）已經產出「使用者確認過的 mockup」。沒有確認過的 mockup，一律不進部署，回報使用者前置階段還沒完成。

## 跟 case-page 的邊界（設計決策，不可打破）

- `case-page` 只做離線自包含 HTML，明文寫死「不部署上網」，這個 skill 完全不動它
- 部署、上網、串 D1、串第三方服務即時示意、素材自動生成，全部收在這個 skill 底下
- 兩個 skill 各自單一職責，互不越界：`case-page` 不判斷要不要部署，這個 skill 不做「離線可看」的產出格式

## 適用時機

- `realtime-need-capture` 已產出「已確認需求資料包」
- 業務員需要在對談當下或對談結束前，給客戶一個可操作的真實網址，而不是死的截圖或簡報

## 本 skill 專責的部署行為

- **前提：風格前置階段（見上）已產出使用者確認的 mockup，否則不進這一步**
- 用確認過的 mockup + 內容生成 Demo 程式碼並部署到 Cloudflare Pages（`--branch=main`，走 Production）
- 需求標記需要登入時，provision Cloudflare D1 並串最簡登入後台；不需要登入時不建立多餘 D1 資源
- **後台功能範圍以「已確認需求資料包」明確列出的功能為準，不多做、不少做**：資料包沒明講的功能點，一律標示為「示意用」而非做出完整可運作的假功能
- Demo 內嵌入第三方服務（如 LINE OA）的即時示意畫面；遇到未支援的服務要顯示明確提示，不能省略
- 缺圖/缺影片時自動生成示意素材，且明顯標示「示意用，非最終素材」
- 部署失敗要回報實際錯誤原因，並保留上一個成功版本網址繼續可用

## 部署機制（複用待神已驗證做法，內容邏輯完全獨立）

參考 `Awesome-Dyson` 的 `scripts/dashboard-deploy.sh`：單一 writer lock 避免同時部署衝突、明確用 `--branch=main`、部署後用穩定 DOM 標記驗證成功與否。只借部署機制的寫法，不共用 state.json/entries 結構——這個 skill 產出的是客製接案 Demo，跟待神儀表板的專案進度內容完全獨立。

## 案神到報價師的交接

需求確認報價後，呼叫方依 `contracts/ANSON-TO-QUOTEMASTER-COMMAND.md` 定義的格式送出指令（`client_id`／`confirmed_price`／`terms`／`case_ref`）。這份文件只定義「送出什麼」，不定義報價師「怎麼處理」——報價師怎麼跑，是報價師那個獨立專案的事。
