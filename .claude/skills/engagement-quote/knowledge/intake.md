# 報價前資料收集

## 最低必要資料

| 類別 | 必填內容 | 狀態 |
|---|---|---|
| 專案身份 | 報價對象、客戶公司、報價公司、聯絡人、Email、地址 | confirmed/pending |
| 文件 | 報價日期、有效期限、統一編號、報價編號 | confirmed/pending |
| 目標 | 客戶要解決的問題、使用者、成功標準 | confirmed/pending |
| 範圍 | 必要功能、非必要功能、加購項目、第三方整合 | confirmed/pending |
| 交付 | 主機／網域／Email／金流／影片／部署責任 | confirmed/pending |
| 商務 | 方案型態、正式價格、付款節點、稅金與費用負擔 | confirmed/pending |
| 保障 | 時程、驗收方式、保固期、支援邊界、資安責任 | confirmed/pending |

## 補問規則

依序優先問：會改變總價的範圍 → 會改變方案的程式碼／授權邊界 → 付款與交付責任 → 文件抬頭與聯絡資料 → 版面偏好。每次只問一題，附上建議答案與「若不確認會造成什麼影響」。

## 專案型態例子

如果是既有平台品牌置換或 SaaS 收款平台，必須分清楚：

- 平台本體是否買斷、租賃或僅代管。
- 客戶是否需要自行維護、部署與擴充。
- 整包程式碼是否交付；若不交付，哪些功能僅提供使用權或鎖定。
- FDE（專職開發工程師）是否是額外的一對一整合服務。
- 保固期內是否包含操作教學、部署協助與第三方服務設定。
