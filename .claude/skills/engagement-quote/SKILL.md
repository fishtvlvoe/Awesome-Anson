# 接案報價

這個 Skill 接在 `/pm` 或其他需求整理流程之後，負責把「做什麼」轉成「報什麼、多少錢、怎麼交付」。適用於網站、SaaS、客製開發、系統整合與數位服務專案。

## GATE：先對焦，不直接報價

先用白話複述：需求來源、報價對象、預計交付物，以及目前已確認／待確認的內容。接著只能一次問一個最關鍵的問題，並提供建議答案；能從檔案或程式碼確認的內容先自己查，不問使用者已提供的資料。

在使用者回覆「OK／確認」前，不產生正式報價金額、不輸出正式 HTML/PDF。

複雜、跨系統、價格分歧大，或術語尚未定義時，先建議使用 `/grill-with-docs`，讓詞彙與不可逆決策留下 `CONTEXT.md`／ADR，再回到本流程。

## 流程

1. 讀取 PM/FRD、Demo、既有報價單與專案規則，建立 `quote data pack`。
2. 將每個欄位標成 `confirmed`、`pending` 或 `inferred`；`inferred` 不得直接當成客戶承諾。
3. 依 `knowledge/intake.md` 一題一題補問，直到正式報價門檻全部確認。
4. 依 `knowledge/pricing.md` 分成必要、非必要、加購／選配；各自列項、各自小計，替代方案不重複加總。
5. 先呈現文字圖解與價格表，等使用者確認後，再產出完整報價文件。
6. 依 `knowledge/document-sections.md` 生成 HTML；用瀏覽器或 PDF 工具輸出 PDF。
7. 依 `knowledge/verification.md` 驗證內容、金額、頁面、PDF 可讀性與 Git 狀態。

## 強制停止點

- PM/FRD 摘要完成後：請使用者確認理解是否正確。
- 必要／非必要／加購價格表完成後：請使用者確認正式價格。
- HTML 初版完成後：請使用者確認文字、配色與版面，再輸出最終 PDF。

## 品質檢查

- [ ] 沒有憑空新增功能、價格、時程或承諾。
- [ ] 必要、非必要、加購／選配各有明確小計，總價可重算。
- [ ] 所有專有名詞都有中文解釋或備註。
- [ ] 交付、驗收、時程、付款、假設／排除／變更、保固／資安均有內容。
- [ ] HTML 與 PDF 的金額、日期、頁數與主要段落一致。

## 完成條件

- [ ] 使用者已確認報價資料與正式價格。
- [ ] quote data pack、HTML、PDF 與驗證結果已留存。
- [ ] Git 只提交本次報價相關檔案，commit 與 remote 狀態已明確回報。
