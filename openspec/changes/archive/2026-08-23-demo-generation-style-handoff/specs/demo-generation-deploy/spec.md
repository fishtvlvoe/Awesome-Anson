## MODIFIED Requirements

### Requirement: Generate a live demo site from confirmed requirements

The system SHALL generate a working demo web application from a confirmed requirements data pack and deploy it to Cloudflare Pages so the client can operate it during the same meeting. Before deployment, the system SHALL first complete the style-and-content pre-stage defined below (delegation to `網頁設計師`, and to `簡報師` when narrative content is involved); the system SHALL NOT deploy a demo whose visual presentation was generated by this capability itself rather than produced and confirmed through that pre-stage.

#### Scenario: Deployment succeeds and returns a usable URL

- **WHEN** a confirmed requirements data pack is passed to this capability, and the style-and-content pre-stage has completed with a confirmed mockup
- **THEN** the system SHALL deploy the generated demo to Cloudflare Pages using the production branch, and SHALL return a URL that responds with HTTP 200

#### Scenario: Deployment failure is surfaced, not hidden

- **WHEN** the Cloudflare Pages deployment fails for any reason (quota, name collision, build error)
- **THEN** the system SHALL report the actual failure reason to the caller and SHALL leave any previously deployed working version for that client still reachable at its existing URL

#### Scenario: Deployment is blocked until the pre-stage mockup is confirmed

- **WHEN** this capability is invoked before the style-and-content pre-stage has produced a user-confirmed mockup
- **THEN** the system SHALL NOT proceed to deployment, and SHALL report that the pre-stage must complete first

## ADDED Requirements

### Requirement: Anson dispatches specialist capabilities; they do not self-trigger

Within an active client engagement, `網頁設計師`, `案例設計師`, `簡報師`, `demo-generation-deploy`, and `case-page` SHALL only be invoked as a result of a dispatch decision made by 案神（the orchestrating session driving the engagement）. None of these capabilities SHALL trigger themselves or each other autonomously based on their own judgment of when they should run.

#### Scenario: A specialist capability does not act without being dispatched

- **WHEN** an active client engagement is in progress and no dispatch decision has directed a given specialist capability to run
- **THEN** that capability SHALL remain idle regardless of what state the engagement is in

### Requirement: Style-and-content pre-stage before demo deployment

Before `demo-generation-deploy` proceeds to deployment, 案神 SHALL delegate visual style production to `網頁設計師`, which SHALL use `案例設計師`'s SaaSFrame case index as one of its reference sources alongside its existing external references (21st.dev, motionsites.ai, Pinterest). `網頁設計師`'s involvement SHALL stop once it produces a user-confirmed HTML mockup; its own Phase 2 deployment flow (Codex sites-building/sites-hosting) SHALL NOT be used for this handoff, because `demo-generation-deploy` alone handles the D1-backed login backend this capability requires.

#### Scenario: 網頁設計師 produces a confirmed mockup before deployment proceeds

- **WHEN** 案神 delegates style production for a demo to `網頁設計師`
- **THEN** `網頁設計師` SHALL run its existing Phase 1 flow (style direction discussion, reference gathering including `案例設計師`'s case index, `frontend-design` skill review, mockup production, user confirmation) and SHALL stop before its own Phase 2 deployment flow

#### Scenario: Narrative content is delegated to 簡報師 only when the demo needs it

- **WHEN** the confirmed requirements data pack indicates the demo includes narrative or presentation-style content (for example, a product story or a paged walkthrough)
- **THEN** 案神 SHALL delegate that content to `簡報師`, which SHALL use its existing page-by-page structure confirmation flow, and the resulting content SHALL be merged into the mockup `網頁設計師` produces

#### Scenario: Narrative delegation is skipped for purely functional demos

- **WHEN** the confirmed requirements data pack describes a purely operational or data-driven demo with no narrative content
- **THEN** 案神 SHALL NOT delegate to `簡報師` for that engagement

### Requirement: Backend scope is bounded by the confirmed requirements pack

The system SHALL limit the demo's backend functionality to what the confirmed requirements data pack explicitly lists. Functionality not explicitly listed SHALL be rendered as an illustrative placeholder rather than built as working functionality.

#### Scenario: Unlisted functionality is not silently built

- **WHEN** a plausible backend feature is not explicitly present in the confirmed requirements data pack
- **THEN** the system SHALL NOT implement that feature as working functionality, and SHALL mark any related UI element as illustrative if it appears at all

### Requirement: Skipping the style pre-stage requires an explicit stated reason

案神 MAY skip delegating to `網頁設計師` for a given engagement only in cases where the demo has no visual presentation to design (for example, a purely data/text output the client will read programmatically). When skipped, 案神 SHALL state the reason in its report to the user rather than skipping silently.

#### Scenario: Skip is stated, not silent

- **WHEN** 案神 decides not to delegate style production for a given demo
- **THEN** the report to the user SHALL explicitly state that the style pre-stage was skipped and why
