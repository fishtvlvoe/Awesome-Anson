案件分析工具包 · 使用說明書

案神是你的接案幕僚：把客戶的模糊想法，整理成可以一起確認的方案。

客戶可能只說「我想做個網站」、「想把流程自動化」，但這還不是可以報價的需求。案神先幫你聽懂對方真正要解決的問題，再整理成需求、報價、簡報，必要時做一個客戶當場能操作的 Demo。

你可以把它想成會議旁邊的白板。客戶講話時，白板幫你記下重點、圈出還不確定的地方；但最後要不要答應、收多少錢、什麼時候交，仍然由你確認。

讀法說明

這份說明書怎麼標記內容

案神教它的 PM 助理，把每一項需求標成「已確認 / 待確認 / 我猜的」三種狀態。這份說明書用同一套方法標記自己：對照原始檔案逐字核對過的，蓋「已確認」；還在規劃、尚未真的落地的，老實蓋「待確認」或「我猜的」，不裝作它已經是一個現成工具。

已確認 對照原始檔案逐字核對過
待確認 有明確規劃方向，還沒真正落地
我猜的 推測或尚未存在，需要 Fish 確認

先看一個案子

客戶只說：「我想做一個網站。」案神會怎麼接住？

下面不是假裝自動成交的戲，而是把案神真正做的事拆成四個你看得懂的動作。按下面四格，看同一句客戶話怎麼一步步變成可以討論的方案。

客戶在會議上說
「我們想做一個網站，讓客人可以直接預約，最好也能自動提醒。」
第一步｜先不急著報價

把客戶的話完整留下來

案神先記住客戶真的說了什麼，不急著把「想要網站」翻成某個技術方案。因為同一句話，可能代表預約、收款、會員管理，範圍差很多。

這一步你會拿到 一份不加戲的對談重點

已確認：客戶想讓客人預約，也希望有提醒。還沒有確認：要用什麼平台、誰管理、預算多少。

客戶說的話

是線索，不等於完整需求。案神會保留原意，不替客戶擅自做決定。

你確認過的話

才是下一位助理可以拿去算價格、寫提案的內容。

最後交給客戶的東西

是你看過的需求、報價、簡報或 Demo，不是 AI 自己偷偷送出去的結果。

跟客戶怎麼接

案神不是直接對客戶下指令，而是站在你這邊的中間桌。

白話講：客戶把問題交給你；你把對談、訊息或檔案交給案神；案神整理出下一步；你確認後，才把方案拿回去跟客戶談。

01

客戶說

口頭對談、訊息、會議記錄或既有文件。

02

案神整理

把人話拆成「已知道、還要問、目前只是猜測」。

03

你做確認

補充背景、修正誤解，決定哪些內容真的要做。

04

拿方案回談

報價、簡報、網頁草稿或 Demo，依你的決定交付。

05

成交再交棒

客戶點頭或付訂金後，才把確認好的需求交給蓋神開發。

客戶需要做什麼？

很少

客戶不需要安裝案神，也不需要看 12 個工具名稱。客戶只要把問題、期待與限制說清楚，後面由你帶著確認。

你要掌握什麼？

不能省

你決定需求有沒有聽對、價格能不能承諾、哪些地方要人工補資料，以及什麼時候可以交付。

案神不會做什麼？

邊界

不會替你答應客戶、不會把猜測當定案、不會在你沒確認時把 Demo 發出去，也不是一個自己在背景工作的客服機器人。

助理

4 位助理：像公司裡分工清楚的同事

你不用先背 Agent 是什麼。把它想成四位有專長的同事：有人負責聽懂需求、有人負責報價、有人負責簡報、有人負責整理課程。你點名誰，誰才開始工作；不會所有人一起亂改。

需求分析助理project-manager

已確認

像會議記錄員加問題整理員

把客戶逐字稿、會議記錄整理成「已確認的需求」，交出一份下一位助理能直接接手的整理檔。它不自行承諾價格，也不把自己的推測寫成客戶已經決定的事。

  • 每一項需求都標「已確認 / 待確認 / 我猜的」
  • 交出去的檔名固定，方便接手：PM-TO-QUOTE-DATA-PACK.md
  • 案子複雜、資訊不夠時，會先用一個叫 pm-discovery-upgrade 的工具，一題一題問你，把缺的資訊補齊

報價與提案助理commercial-proposal-quotation-specialist

已確認

像把需求整理成合約前試算表的顧問

把 PM 整理好的需求算成價格、寫成條款，變成客戶看得懂、金額可重算、責任邊界清楚的提案。先出網頁版給客戶看，客戶點頭才轉成正式 PDF。

  • 算價格的動作其實是一個叫 engagement-quote 的工具在背後跑，這位助理負責把結果包裝成你看得懂的提案
  • 轉 PDF 前一定先給你看過網頁版

簡報助理簡報師

已確認

像把提案整理成一頁一頁的人

把簡報想法、完整文案、報價單整理成你能確認的逐頁內容。大綱確認後，你選一條路：Kimi 網頁提詞，或本機工具做出正式 .pptx 檔。簡報師自己不會自動送出、也不會自己生出 .pptx 檔案。

  • Kimi 路徑用 kimi-slide 產生提詞，你自己貼去 Kimi 網站
  • 本機路徑產出交接包，給 ppt-master 接手做出真正的檔案

課程整理助理開課師

已確認

旁支工作，跟接案報價無關

拿主題、素材跟講師經驗，走完六階段開課流程，交付課程綱要、簡報中繼稿、簡報輸出跟學員 PDF 講義。算附贈功能，不影響上面三位接案助理的流程，也不會被入口指令呼叫到。

工具

12 個功能工具：你不用背名字，先說你要做什麼

工具就是一個已經準備好的小幫手。你可以叫助理使用，也可以直接用白話描述想完成的事。下面先寫「它幫你做什麼」，技術名稱放在下面讓需要對照檔案的人查。另有一批 Spectra 開發工具只用來維護案神，不算客戶接案成果。

生成與計算引擎

把需求算成報價engagement-quote · 報價助理背後的工具
把已經確認好的需求算成一份可核對的報價資料，跟一份網頁／PDF 報價單。這是報價顧問實際在用來算價格的工具，不是另一個獨立功能。
做一份打開就能看的提案網頁case-page · 和簡報助理平行的輸出
把已經確認好的提案內容，做成一份網頁檔案，不用架任何伺服器、不用申請帳號，雙擊打開瀏覽器就能看。它只負責「做出這份檔案」，至於要不要放到網路上讓別人看、要不要設密碼或到期時間，交給呼叫它的人自己決定。
做一個客戶能點的示範版demo-generation-deploy · 確認後才使用
把已確認的需求資料包與使用者確認過的 mockup，生成客戶當場能操作的 Cloudflare Pages Production Demo。需要登入才配置 D1；第三方服務、缺少的圖片或影片會明白標成示意，不假裝已經完成。

簡報產出（簡報師背後的兩條路）

把內容整理成簡報提詞kimi-slide · 簡報助理的 Kimi 路徑
把素材或想法收斂成一份中繼文件，依 Kimi PPT 官方建議的格式產出提詞文字。只產出提詞，不會自己呼叫 Kimi、不會自己送出。

通用工具（不是接案專屬）

把工程話翻成人話im-human · 語氣整理工具
把讀起來很像 AI 寫的文字，改成像人在說話。兩種用法：一種是讓 Claude 自己講話時就自然一點，另一種是幫你改寫貼文、Email、文案。只處理台灣繁體中文跟英文，不做翻譯，也不會幫你查證內容對不對。
即時語音的現況：收音目前是本機／區網 HTTP，FunASR 在本機辨識，逐字稿寫到 tools/realtime-voice/output/。手機要從公開 HTTPS 網址收音的方案仍在規劃，尚未算成已完成能力。 待確認

入口指令

怎麼叫它

整案分析到報價一條龍走完，打這一行：

$ /client-quote <案件資料夾或逐字稿路徑> # 換成你的檔案路徑
  1. 串起 project-manager → commercial-proposal-quotation-specialist → 簡報師 三位助理接力
  2. 案子複雜會先多問幾輪（這步驟叫 grill-with-docs），一題一題問，答完才問下一題
  3. 需求整理完先給你看摘要，你說「對」才進報價
  4. 報價表跟網頁版你都看過、點頭，才轉成正式 PDF
  5. 報價確認完，中文跟它說「幫我做成簡報」，它自己知道要找簡報師，不用背指令

只想單獨叫某一位助理、不走整條流程：沒有現成斜線指令，直接跟它說「這次麻煩用簡報師的身分幫我」就可以，不用背指令。

對談中即時拆解

已確認

先啟動 tools/realtime-voice/server.py 收音，再請目前的 Agent session 在前景監看逐字稿：

$ venv/bin/python monitor_transcript.py output/<session-id>.md

停頓超過 3 秒，或連續內容累積到 30 秒，會觸發一次即時分析。沒有監看器時，收音與逐字稿仍可正常使用。

做成可操作 Demo

已確認

把已確認需求交給 demo-generation-deploy。有視覺需求時，必須先由網頁設計師產出並讓你確認 mockup；有敘事內容才另外委派簡報師。

mockup 沒確認不能部署，部署失敗要保留上一個成功網址。這條路和只做離線 HTML 的 case-page 是兩件事。
