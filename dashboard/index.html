CASE FILE / ANSON / v1

案神在幹什麼：把客戶的逐字稿，變成你敢拿去談判的報價單跟簡報。

案神（Awesome-Anson）是一組「丟案件資料進去、吐結構化產出出來」的接案分析架構：4 個 Agent 接力處理需求、報價、簡報；9 個 Skill 在背後被這些 Agent 呼叫，或單獨拿來用。

它不是常駐系統。沒有背景排程、沒有狀態機一直在跑——你打指令或點名它才動，不叫它就完全靜止，像精靈一樣呼之即來、揮之即去。

01 · 讀法說明

這份說明書怎麼標記內容

案神教它的 PM Agent，把每一項需求標成「已確認 / 待確認 / 我猜的」三種狀態。這份說明書用同一套方法標記自己：凡是直接對照原始 .md 檔案寫出來的，蓋「已確認」章；還在規劃、尚未真的存在的，老實蓋「待確認」或「我猜的」章，不裝作它已經是一個現成工具。

已確認 對照原始檔案逐字核對過
待確認 有明確規劃方向，還沒真正落地
我猜的 推測或尚未存在，需要 Fish 確認

02 · Agent

4 個 Agent：各做各的，互不知道對方在忙什麼

「Agent」是一個有固定角色、固定做事規則的身分，你點名它，它才用那個角色的方式做事。

project-manager

已確認

中文角色：專案管理與需求分析師

把客戶逐字稿、會議記錄整理成「已確認的需求」跟一份可交接的 PM 資料包。它不自行承諾價格，也不把自己的推測寫成客戶已經決定的事。

  • 每一項需求都標「已確認 / 待確認 / 我猜的」
  • 交出去的東西有固定長相：PM-TO-QUOTE-DATA-PACK.md
  • 需要多輪訪談時，會先跑 pm-discovery-upgrade 這個 Skill

commercial-proposal-quotation-specialist

已確認

中文角色：商務提案與報價顧問

把 PM 資料包算成價格、寫成條款，變成客戶看得懂、金額可重算、責任邊界清楚的提案。先出網頁版給客戶看，客戶點頭才轉成正式 PDF。

  • 背後真正在做計算的是 engagement-quote 這個 Skill
  • 轉 PDF 前一定先給你看過網頁版

簡報師

已確認

Presentation Manager Agent

把簡報想法、完整文案、報價單整理成可確認的逐頁結構。大綱確認後，你選一條路：Kimi 網頁提詞，或本機 ppt-master 做出正式 .pptx 檔。簡報師本身不會自動送出、也不會自己生出 .pptx 檔。

  • Kimi 路徑用 kimi-slide 產生提詞，你自己貼去 Kimi 網站
  • 本機路徑產出交接包，給 ppt-master 接手做檔案

開課師

已確認

Course Builder Agent · 旁支，跟接案報價無關

拿主題、素材跟講師經驗，走完六階段開課流程，交付課程綱要、簡報中繼稿、簡報輸出跟學員 PDF 講義。算附贈功能，不影響上面三個接案助理的流程，也不會被 /client-quote 呼叫到。

03 · Skill

9 個 Skill：工具函式，不是角色

「Skill」是一包寫好的做事技巧或模板，不會自己判斷、不會自己問問題，被 Agent 呼叫或你自己單獨叫都可以。

訪談與思考工具

pm-discovery-upgradeproject-manager 用
PM Agent 分析需求前，先做一輪一題一題的前期調查，產出可交給報價流程的確認資料包。
grilling通用討論工具
一題一題逼問使用者，直到對計畫、決策或想法有共同理解，把決策拆成一棵「決策樹」。
grill-with-docs通用討論工具
帶著既有文件跑一場 grilling 訪談，邊問邊順手產出 ADR 跟術語表。
domain-modeling通用思考工具
把一個專案的業務領域拆解、鎖定用詞，維護 CONTEXT.md 跟 ADR 記錄。

生成與計算引擎

engagement-quote報價顧問背後的引擎
把已確認的 PM/FRD 需求轉成可核對的接案報價資料包，跟 HTML／PDF 報價單。這是報價顧問實際在用來算價格的引擎，不是另一個獨立功能。
case-page跟簡報師平行的輸出路徑
把已確認的提案內容轉成一份自包含 HTML 頁面，不透過任何外部服務或帳號，開瀏覽器就能看。只負責「生成」，不部署上網、不管帳號、不設密碼或到期時間——這些是呼叫方自己決定的事。

簡報產出（簡報師背後的兩條路）

kimi-slide簡報師的 Kimi 路徑
把素材或想法收斂成中繼 md，依 Kimi PPT 官方建議格式產出提詞文字。只產出提詞，不呼叫 Kimi API，不自動送出。
ppt-master簡報師的本機路徑
把交接包做成真正可編輯的 .pptx 檔，還能重建版面、管理品牌/風格/版型工作區。Python 工具，第一次用要先 pip install -r requirements.txt。

通用工具（不是接案專屬）

im-human語態控制／去 AI 味
把 AI 味的文字改成人話，兩種模式：語態模式讓 Claude 自己說話變自然，編輯模式改寫貼文、Email、文案。只支援台灣繁中跟英文，不做翻譯或事實查核。

04 · 入口指令

怎麼叫它

整案分析到報價一條龍走完，打這一行：

$ /client-quote <案件資料夾或逐字稿路徑> # 換成你的檔案路徑
  1. 串起 project-manager → commercial-proposal-quotation-specialist → 簡報師 三個角色接力
  2. 案子複雜會先多問幾輪（這步驟叫 grill-with-docs），一題一題問，答完才問下一題
  3. 需求整理完先給你看摘要，你說「對」才進報價
  4. 報價表跟網頁版你都看過、點頭，才轉成正式 PDF
  5. 報價確認完，中文跟它說「幫我做成簡報」，它自己知道叫簡報師，不用背指令

只想單獨叫某一位助理、不走整條流程：沒有現成斜線指令，用 Agent 工具直接點名，例如「這次麻煩用簡報師的身分幫我」。

05 · 串接關係

案神跟誰串接

案神是「神系列」家族接力鏈的第一棒。客戶點頭確認提案之後，資料真的會往下傳的只有這幾條線；其餘家族成員只是同一個系列，沒有直接資料交接。
